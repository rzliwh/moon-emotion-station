## 脚本设计说明

### 延迟时间设计逻辑

| 电波 | 延迟时长 | 为什么 |
|------|---------|--------|
| #01 加班等车 | 2小时 | 2h后可能已到家，回信有"上车了"的交代感 |
| #02 食堂摔餐盘 | 30分钟 | 30min后可能开完会了，情绪已消化一半 |
| #03 新房第一晚 | 次日早晨 | 次日早上回信，"新生活好像能过"有翻篇感 |
| #04 面试等待 | 次日早晨 | 面试结果通常第二天出，回信有"通过了"的落地感 |
| #05 晚霞分享 | 1小时 | 即时情绪分享，1h后晚霞还在记忆里，回信能接住 |
| #06 想念面馆 | 次日晚上 | 深夜电波隔天晚上回，"座位给你留着"有跨越一天的温度 |
| #07 周一倦怠 | 傍晚6点 | 下班后回，恰好一天过完，"好像一周也不是很长"收束感 |

**原则：** 延迟时间要卡在"电波主人情绪已经自然消化一部分，但还没完全忘"的时间点。太早回信像自动回复，太晚回信已经没感觉了。

### 回信文案三标准

1. **不感谢，只描述** — 从来不说"谢谢你的帮助"，而是说具体发生了什么（"车来了""衣服上还沾着糖醋汁""冰箱没那么响了"）
2. **轻轻挂钩你的动作** — "从月球上抱了我一下""你种的那颗种子开花了""知道有个地方给我留了盏灯"——把你的动作和 ta 的生活缝在一起，但不硬连
3. **留一个未确认的悬念** — "不知道是不是你哼的那首""是不是你让它来的"——不确定，但愿意相信，这就是共鸣的钩子

### 电波内容类型规划

| 类型 | 核心情绪 | 典型场景 | 延迟时长参考 |
|------|---------|---------|------------|
| 疲惫型 | 被生活压住 | 加班/通勤/深夜独处 | 2-4小时 |
| 小确丧型 | 日常小挫折 | 摔倒/丢东西/被误解 | 30分钟-1小时 |
| 孤独型 | 无人回应 | 搬家/分手/新环境 | 次日早晨 |
| 焦虑型 | 对未来的不安 | 考试/面试/等待结果 | 次日早晨 |
| 温暖型 | 想分享小确幸 | 晚霞/好消息/小惊喜 | 即时或1小时 |
| 想念型 | 旧人旧事 | 路过故地/深夜回忆 | 次日晚上 |
| 倦怠型 | 机器感循环 | 周一早晨/重复工作日 | 下班后 |

### 后续扩写方向

- 每种类型再写 3-5 条，形成 15-25 条电波库
- 加入季节性电波：中秋/月圆/新年/流星雨

## 技术实现说明

### 延迟回信方案（正式版）

**方案：localStorage + 时间戳**

```
流程：
1. 玩家选择动作 → 记录 { 电波ID, 选项, 时间戳 } 存入 localStorage
2. 玩家下次打开页面 → 检查 localStorage 中所有待回信记录
3. 如果 当前时间 - 选择时间 >= 延迟时长 → 弹出回信 + 更新月球痕迹
4. 如果还没到时间 → 显示"等待中"状态（如：信号还在传输……）
5. 回信展示后 → 标记为已读，月球痕迹永久保留
```

**为什么正式版也用这个方案：**
- 纯前端，不需要后端服务器
- GitHub Pages 部署即可运行
- 关闭页面再打开，延迟逻辑仍然有效
- 同一浏览器/设备体验连续（换设备会丢失，但对于这个游戏可以接受——它不是存档型游戏，是体验型游戏）

### 月球痕迹存储

localStorage 结构：
